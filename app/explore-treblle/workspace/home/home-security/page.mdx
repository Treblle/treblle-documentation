# Security

The **Security** tab provides a real-time overview of your API security posture across all environments, gateways, and services. It aggregates key safety metrics into a single view so you can quickly understand what risks exist across your APIs.

<NoteCard>
The Security tab requires a **Team** or **Enterprise** plan.
</NoteCard>

<ImageCard src="/Home - security.png" alt="Home Security Dashboard" />

## Security Overview Cards

Four top-level metrics summarize the overall security state of your workspace:

<ImageCard src="/Home - security - 1.png" alt="Security Overview Cards" />

### Security Fail
Number of APIs currently failing security checks.

- Indicates immediate security risks requiring attention
- Shows count with percentage change trend

### Problematic APIs
Number of APIs with detected security issues or vulnerabilities.

- Helps prioritize remediation efforts
- Shows count with percentage change indicator

### Zombie APIs
APIs that exist but show little or no recent activity — often forgotten and unmaintained.

- Increases attack surface and maintenance burden
- Shown as a total count with trend

### Compliance Fail
Number of APIs failing compliance checks across the workspace.

- Essential for maintaining GDPR, PCI DSS, HIPAA compliance
- Shows count with percentage change

## Vulnerability Analysis

### OWASP Top 10

Tracks API security issues aligned with OWASP standards.

<ImageCard src="/Home - security - 4.png" alt="OWASP 10 Widget" />

- **OWASP**: Category of security risk classified as API#1–10
- **Endpoints**: Shows affected endpoints as a percentage
- **Status**: Typically marked as Fail

### BOLA (Broken Object Level Authorization)

Lists APIs vulnerable to object-level access issues.

- **API**: Name of the API
- **BOLA #**: Number of requests that failed the BOLA check
- **Status**: Usually marked 403 Forbidden

### BFLA (Broken Function Level Authorization)

Shows APIs vulnerable to function-level authorization flaws.

- **API**: Name of the API
- **BFLA #**: Number of requests that failed the BFLA check

## API Visibility and Authentication

### Zombie APIs List

Lists specific APIs that are inactive or abandoned.

- **API**: Name of the API
- **Last Active**: Last time this API was active

### Unsecured APIs

Highlights APIs lacking proper authentication.

- **API**: Name of the API
- **Authentication**: Bearer Token / OAuth, API Key, Basic Auth, or None/Unknown

### Authentication Type

Displays the authentication method in use per API and its security status.

- **API**: Name of the API
- **Authentication**: Basic, Bearer, Custom, or No Auth
- **Status**: Secure, Risky, or No Auth

---

## Consumer and Data Risk

### Risky Consumers

Shows consumers whose request patterns indicate elevated risk.

- **Consumer**: Which consumers are involved
- **API**: Which APIs they interacted with
- **Failed Requests**: Number of failed or problematic requests

### Sensitive APIs

Highlights APIs that may expose sensitive or PII data.

- **API**: API name
- **Risk**: Severity level (Low, Medium, High)
- **Issues**: Number of detected issues
- **Occurrences**: Frequency of incidents
- **Last Occurrence**: Most recent detection

---

## API Type Distribution

### APIs by Type

Breakdown of APIs by exposure type:

- **Internal**
- **External**
- **Partner**

Helps assess security risk across different API audiences.

## Filters & Controls

At the top-right of the dashboard, you can filter data by:

- **Environment** (e.g. production, staging)
- **Category** (e.g. end user, department)
- **Time range** (e.g. last 24 hours)
